# وثيقة مواصفات متطلبات البرمجيات
## نظام GymBro — بوابة إدارة الصالات الرياضية

---

## 1. المقدمة

### 1.1 الغرض

تصف هذه الوثيقة متطلبات بوابة إدارة نظام GymBro على الويب، وتُعد المرجع المعتمد لفريق التطوير والاختبار.

### 1.2 النطاق

بوابة ويب تخدم دورين إداريين:

- **المشرف العام:** يدير المنصة كاملةً — الصالات ومديريها، والمدربين والمتدربين، والمحتوى التدريبي المشترك.
- **مدير الصالة:** يدير صالة واحدة مُسندة إلى حسابه — ملفها وخططها واشتراكاتها وأعضائها وحضورهم.

يقع خارج النطاق: تطبيق الهاتف للمتدربين والمدربين، وبوابة الدفع، وخدمة تخزين الصور؛ إذ يتعامل النظام معها بوصفها أنظمة خارجية.

---

## 2. وصف عام

### 2.1 المستخدمون

| الدور | نطاق صلاحيته |
| :--- | :--- |
| المشرف العام | جميع الصالات وبيانات المنصة |
| مدير الصالة | الصالة المُسندة إليه فقط |

لا يوجد تسجيل ذاتي؛ فحساب مدير الصالة يُنشئه المشرف العام عند إنشاء الصالة.

### 2.2 بيئة التشغيل

تطبيق ويب مبني بـ Next.js 16 و React 19 و TypeScript، بتنسيق Tailwind CSS ورسوم بيانية بمكتبة Recharts. لا يملك النظام قاعدة بيانات خاصة، بل يستهلك واجهة REST من الخادم الخلفي عبر Axios.

## 3. المتطلبات الوظيفية

### 3.1 المصادقة

- تسجيل الدخول بالبريد وكلمة المرور، مع اختيار الدور (مشرف عام أو مدير صالة) قبل الإرسال.
- حفظ رمز الوصول ورمز التجديد والدور عند نجاح الدخول، وإرفاق رمز الوصول تلقائيًا مع كل طلب محمي.
- التوجيه إلى لوحة التحكم الخاصة بالدور بعد الدخول.
- منع فتح صفحات دور لا يملكه المستخدم.
- إنهاء الجلسة والعودة إلى شاشة الدخول عند تلقي الاستجابة `401`.
- استعادة كلمة المرور لمدير الصالة: طلب رمز تحقق بالبريد، ثم تعيين كلمة مرور جديدة برمز مكوَّن من ستة أرقام.
- تسجيل الخروج مع مسح بيانات الجلسة.

### 3.2 بوابة المشرف العام

**لوحة التحكم**
- الأعداد الإجمالية للصالات والمدربين والمتدربين.
- رسم بياني لتوزيع الصالات حسب نوعها.
- ملخص إحصاءات الاشتراكات.

**الصالات الرياضية**
- عرض قائمة الصالات مع البحث والتصفح بالصفحات.
- إنشاء صالة جديدة: الاسم والنوع والهاتف والوصف والإحداثيات، مع بيانات حساب مديرها في العملية نفسها.
- التحقق من أن خط العرض بين -90 و 90 وخط الطول بين -180 و 180.
- عرض تفاصيل الصالة شاملةً بيانات مديرها وخططها.
- حذف الصالة بعد تأكيد صريح.

**المدربون**
- عرض القائمة مع البحث والتصفح بالصفحات.
- إضافة مدرب: الاسم والبريد وكلمة المرور والهاتف والنبذة وسنوات الخبرة وروابط التواصل الاجتماعي وحالة التوثيق.
- عرض تفاصيل المدرب.

**المتدربون**
- عرض القائمة مع البحث والتصفح بالصفحات.

**التمارين**
- عرض فهرس التمارين مع البحث والتصفح بالصفحات.
- عرض تفاصيل التمرين: الصورة والوصف والمستوى والعضلات المستهدفة.

**مجموعات العضلات والمعدات**
- إنشاء العنصر وتعديله وحذفه.
- إلزام إدخال الاسم بالعربية والإنجليزية معًا.
- تفعيل العنصر أو تعطيله.

**جداول التمارين**
- إنشاء الجدول وتعديله وحذفه.
- بناء الجدول من أيام، يضم كل يوم تمارين، ويضم كل تمرين مجموعات بعدد التكرارات والوزن وثواني الراحة والمدة.
- اختيار التمارين من الفهرس عبر أداة بحث وتصفية حسب المستوى ومجموعة العضلات والمعدات.
- إعادة ترتيب الأيام والتمارين داخل الجدول.
- منع الحفظ عند: غياب الاسم بأي من اللغتين، أو خلو الجدول من الأيام، أو خلو اليوم من اسم، أو وجود تمرين غير محدد، أو تمرين بلا مجموعات — مع الانتقال إلى موضع الخطأ وإبرازه.

**المعاملات**
- عرض إحصاءات الاشتراكات والمدفوعات على مستوى المنصة.

### 3.3 بوابة مدير الصالة

**لوحة التحكم**
- مؤشرات الحضور: اليوم والأسبوع والشهر.
- ساعة الذروة والاشتراكات الجديدة.
- توزيع الأعضاء على الخطط.

**ملف الصالة**
- عرض بيانات الصالة المُسندة إلى المدير.
- تعديل الاسم والوصف والهاتف والإحداثيات، ورفع الشعار.
- إضافة فترات العمل وتعديلها وحذفها؛ وتتضمن الفترة يوم الأسبوع ووقت البداية والنهاية والفئة المستهدفة.
- تفعيل خدمات الصالة أو تعطيلها من القائمة الكاملة للخدمات.
- التراجع عن التعديلات غير المحفوظة.
- فتح موقع الصالة على خرائط Google.
- منع الحفظ عند خلو الاسم أو الهاتف، أو خروج الإحداثيات عن نطاقها، أو انتهاء فترة عمل قبل بدايتها.

**معرض الصور**
- رفع صورة مع وصف اختياري، وعرض معاينة قبل الرفع.
- حذف صورة بعد تأكيد.
- إعادة ترتيب الصور وحفظ الترتيب، مع التنبيه إلى وجود ترتيب غير محفوظ.

**رمز QR**
- عرض رمز QR الخاص بالصالة مع تعليمات استخدامه في الاستقبال.
- إعادة توليد الرمز، مع التنبيه إلى أن ذلك يُبطل الرمز السابق فورًا.

**خطط العضوية**
- عرض الخطط بأسعارها ومددها وحالة تفعيلها.
- إنشاء خطة وتعديلها.
- تعطيل خطة نشطة، وإعادة تفعيل خطة معطّلة.
- حذف خطة بعد تأكيد، مع التنبيه إلى تعذّر حذف خطة لها اشتراكات.
- منع الحفظ عند خلو الاسم، أو خروج المدة عن النطاق من 1 إلى 3650 يومًا، أو كون السعر سالبًا.

**الاشتراكات**
- عرض طلبات الاشتراك مع تصفيتها حسب الحالة.
- عرض اسم العضو والخطة والسعر والمدة وتاريخي البداية والنهاية وطريقة الدفع والحالة.
- الموافقة على الطلبات المعلّقة المدفوعة نقدًا.
- رفض أي طلب معلّق.
- إلغاء اشتراك نشط أو اشتراك طُلب إلغاؤه، مع اختيار نوع الإلغاء: فوري أو عند نهاية الفترة المدفوعة.
- طلب تأكيد صريح قبل كل إجراء، وتحديث القائمة بعده.
- عرض ملخص بعدد الطلبات المعلّقة والاشتراكات النشطة وقيمتها.

**الأعضاء**
- عرض قائمة الأعضاء مع التصفح بالصفحات.
- البحث بالاسم أو البريد الإلكتروني.
- الترتيب حسب تاريخ البداية أو النهاية، تصاعديًا أو تنازليًا.
- عرض الملف التفصيلي للعضو: اشتراكه الحالي واشتراكاته السابقة وسجل حضوره وإجمالي زياراته.
- إبراز الأعضاء الذين تنتهي عضويتهم خلال سبعة أيام أو أقل.

**سجل الحضور**
- عرض سجلات الحضور مع تصفيتها حسب تاريخ محدد.
- عرض وقت الدخول ووقت الخروج ومدة الجلسة لكل سجل.
- تمييز السجلات التي لم يُسجَّل لها خروج بوصف "ما زال بالداخل".
- عرض مؤشرات موجزة: عدد مرات الدخول، والأعضاء المختلفون، ومتوسط مدة الجلسة، وعدد المتواجدين حاليًا.
- البحث عن عضو داخل السجلات المعروضة.

**التحليلات**
- تحليلات الحضور لليوم والأسبوع والشهر، وساعة الذروة ويوم الذروة ومتوسط الحضور اليومي.
- عدد الخطط النشطة والمعطّلة.
- توزيع الأعضاء النشطين على الخطط.

**الملف الشخصي**
- عرض بيانات المدير وتعديل اسمه وبريده وهاتفه.

## 4. قواعد العمل

1. تُسند كل صالة إلى مدير واحد، ولا يرى المدير بيانات صالة أخرى.
2. تُقبل الموافقة على الاشتراكات المعلّقة المدفوعة نقدًا فقط؛ أما المدفوعة بالبطاقة فتُفعَّل تلقائيًا عند إتمام الدفع.
3. يجوز رفض أي اشتراك معلّق بصرف النظر عن طريقة دفعه.
4. يجوز إلغاء الاشتراك النشط أو الذي طُلب إلغاؤه فقط.
5. لا يجوز حذف خطة لها اشتراكات؛ ويُكتفى بتعطيلها.
6. لا يؤثر تعطيل الخطة على الاشتراكات القائمة عليها.
7. تتراوح مدة الخطة بين يوم واحد و 3650 يومًا، ولا يقل السعر عن الصفر.
8. تُبطل إعادة توليد رمز QR الرمزَ السابق فورًا.
9. تبدأ جميع التعدادات من الصفر، والقيمة `0` قيمة صحيحة ذات معنى لا تُعامل معاملة القيمة الفارغة.

## 5. المتطلبات غير الوظيفية

**الأمان**
- تتم جميع الاتصالات عبر HTTPS.
- لا يُعرض أي مسار محمي قبل التحقق من الجلسة ومن مطابقة الدور.
- تُمسح بيانات الجلسة عند تسجيل الخروج أو انتهاء صلاحية الرمز.

**الأداء**
- تعتمد جميع القوائم الطويلة التصفح بالصفحات بدلًا من التحميل الكامل.
- يُؤجَّل تنفيذ البحث أثناء الكتابة تفاديًا للطلبات المتلاحقة.
- يُحمَّل فهرس التمارين مرة واحدة في الجلسة عند استخدامه في باني الجداول.

**قابلية الاستخدام**
- عرض حالة تحميل أثناء جلب البيانات، وحالة فارغة واضحة عند غيابها.
- عرض رسالة عند نجاح كل عملية أو فشلها، مستخرجة من استجابة الخادم.
- طلب تأكيد صريح قبل الحذف أو الإلغاء.
- عرض التسميات نصوصًا مقروءة لا قيمًا رقمية.
- دعم شاشات الحواسيب واللوحيات والهواتف.

**اللغة**
- دعم العربية والإنجليزية في كامل الواجهة.
- تحويل اتجاه الواجهة إلى اليمين عند اختيار العربية.
- حفظ اللغة المختارة بين الجلسات.

**قابلية الصيانة**
- تُعرَّف قيم التعدادات في موضع مركزي واحد تستورد منه جميع الصفحات.

## دورة حياة الاشتراك

| من | إلى | المُحفِّز |
| :--- | :--- | :--- |
| — | `Pending` | تقديم المتدرب طلب اشتراك |
| `Pending` | `Active` | موافقة المدير على طلب نقدي، أو إتمام الدفع الإلكتروني |
| `Pending` | `Rejected` | رفض المدير للطلب |
| `Active` | `CancelRequested` | طلب المتدرب إلغاء اشتراكه |
| `Active` أو `CancelRequested` | `Cancelled` | إلغاء المدير للعضوية |
| `Active` | `Expired` | بلوغ تاريخ النهاية |
